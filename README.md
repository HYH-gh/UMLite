# UMLite · 文本驱动 UML 绘图工具

`v1.20`　`零依赖`　`离线可用`　`MIT`

**UMLite** 是一个纯前端、文本驱动的 UML 绘图工具。你只需在左侧编辑器中书写简单的文本描述，右侧预览区域便会**实时**渲染出对应的 UML 图形。无需安装、无需注册、无需网络，一个 HTML 文件搞定所有 UML 绘图需求。

> 📄 **一句话用法**：打开 `UMLite.html` → 写代码 → 自动出图 → 导出 PNG / SVG。
>
> 🔔 **更新公告**：点页面右下角的版本号 `v1.20` 可查看历次更新；首次打开（或版本变化后）会自动弹出一次，已读记录存在浏览器本地。完整日志见 [docs/CHANGELOG.md](docs/CHANGELOG.md)。

## ✨ 功能特性

- **纯前端，零依赖** — 单个 `.html` 文件，双击即用，离线可用
- **实时渲染** — 编辑代码即刻预览，无需手动触发
- **增量渲染** — 只改注释、空行时自动跳过重排：画布不跳动，手动拖出来的坐标也不会被打字冲掉；结构变化才重新布局，且布局结果可复现（无随机数）
- **可测试** — 自带 36 条 DSL 断言 + 22 项页面级冒烟 + 4 项发布一致性检查，`node tests/run.mjs` 一条命令跑完，也可在浏览器打开 `tests/index.html`
- **10 种 UML 图** — 类图、用例图、活动图、时序图、E-R 图、状态图、组件图、部署图、对象图、包图
- **力导向布局** — 元素自动排布，无需手动指定坐标
- **交互式画布** — 拖拽元素、滚轮缩放、空白处拖拽平移
- **可撤销** — 画布上的拖拽、增删折点都能 `Ctrl+Z` 回退、`Ctrl+Shift+Z` 重做（一次拖拽 = 一步；编辑器内保持系统原生文本撤销，两套互不打架）
- **响应式** — 桌面 / 平板 / 手机自动适配；≤720px 收成单栏并用「代码 / 预览」标签切换，代码区铺满高度
- **触屏手势** — 双指捏合缩放（跟着两指中点走）、单指拖拽元素与空白处平移、双击连线加折点 / 双击折点删除
- **智能代码补全** — 图类型支持中英文别名
- **SVG / PNG 导出** — 矢量图高清导出，PNG 支持 2x 缩放
- **语言规范文档** — 内置完整语法文档，一键下载 `.md`
- **示例系统** — 每种图类型均带预设示例，一键载入
- **中文友好** — 完整的**中文**标识符支持，文档和界面均为中文
- **可选系统边界框** — 用例图支持 `boundary` + `:boundary` 标记，四角拖拽调大小、支持虚实线
- **活动图泳道与活动边** — 泳道划分，元素归入泳道并随泳道移动，活动边划定区域
- **连线折点折线** — 手动添加折点，绘制横向 / 纵向直角连线
- **智能布局优化** — 类图正交化逼近横平竖直、活动图 / 状态图分层降低交叉、用例图防重叠、连通分量聚簇初始排布
- **完整顺序图（时序图）** — 角色/对象与版型图标（控制类、实体类、边界类）、生命线、激活条、多类型消息、组合片段
- **位置代码（@layout）** — 用绝对坐标预定义元素的默认渲染位置，支持元素/泳道/顺序图各对象，画布拖动后**自动反写**，双向 round-trip
- **导入 / 反写 .uml** — 从文件导入、拖入 `.uml` 自动解析；「反写代码」把画布当前位置写回编辑器
- **顺序图可调节** — 组合片段四角调整大小、生命线统一高度手柄、激活条上下端点调节长度等，均可通过位置代码定义
- **业务模型支持** — `business` 前缀表达业务领域元素（业务角色、业务用例、业务边界/控制/实体对象、业务工人），原子复用普通图形并叠加一条与主体同色的实线斜杠作为区分
- **顺序图大字号参与者** — 参与者（含业务模型）默认以 1.5 倍放大渲染，图标、标签、业务斜杠一并放大，清晰易读

## 🚀 快速开始

1. 在浏览器中打开 `UMLite.html`
2. 从顶部下拉菜单选择一个示例（如「类图 · 电商系统」）
3. 左侧代码区即显示对应 DSL 代码，右侧实时渲染出 UML 图形
4. 任意修改代码，画布自动更新
5. 点击「下载 PNG」或「下载 SVG」导出结果

### 最小示例

以下是一个完整的类图 DSL：

```
@diagram class "Hello UML"

class Hello {
    + sayHello(): String
}

class World
Hello --> World : greet
```

## ⌨️ DSL 语法速览

### 文档结构

```
@diagram <类型> ["图标题"]

// 注释以 # 或 // 开头
语句 1
语句 2
```

### 关系运算符

| 运算符 | 含义 |
|--------|------|
| `-->` | 有向关联 |
| `--` | 无向关联 |
| `--|>` | 继承 / 泛化 |
| `..|>` | 接口实现 |
| `..>` | 依赖 |
| `*--` | 组合 |
| `o--` | 聚合 |
| `..` | 虚线关联 |

### 各图类型语法要点

**类图：** `class 名称 { 成员 }` / `interface 名称 { 成员 }` / `abstract class 名称`
**用例图：** `actor 角色` / `usecase 用例 [:boundary]` / `boundary "系统名称"` / 业务模型：`business actor 业务角色` / `business usecase 业务用例`
**活动图：** `start` / `:动作;` / `if(条件)`...`endif` / `while`...`endwhile` / `note:文本` / 泳道 `in "泳道名"` / 活动边 `edge`
**E-R 图：** `entity 名称 { * 字段 }` / `||--o{` 一对多 / `||--|{` 强制一对多 / `||--||` 一对一 / `||--o|` 一对零或一
**时序图：** `actor/object/control/entity/boundary 名称` / `A -> B : 消息` / `A --> B : 返回` / `activate A` / `deactivate A` / `alt ... else ... end` / `loop` / `opt` / `ref` / 业务参与者：`business actor/object/control/entity/boundary/worker 名称`

**位置代码（`@layout` 块，附加在代码末尾）：**
```
@layout
boundary @ (x, y) w h              // 用例图系统边界 / 活动边，左上角坐标
lane 泳道名 @ (x, y) w h           // 活动图泳道
节点名   @ (x, y) w h              // 类/用例/状态等具名节点，中心坐标
participant 名 @ (x, y) w h        // 时序图参与者
message 序号   @ (_, y)            // 时序图消息（仅纵向，_ 不约束水平）
activation 序号 @ (_, y) h         // 时序图激活条（顶部 y + 高度 h）
fragment 序号 @ (x, y) w h         // 时序图组合片段
lifeBottom  y                      // 时序图全部生命线统一底部高度
```
画布上拖动 / 调整元素后，执行「反写代码」会把当前位置自动写回该块，实现双向 round-trip。
**状态图：** `state 名称` / `A --> B : 事件` / `[*]` 表示起始/终止

## 📱 响应式与触屏

| 视口 | 布局 |
|---|---|
| > 1024px | 左右双栏，分隔条可拖拽，面板栏显示操作提示徽章 |
| 721–1024px | 双栏保留，头部与面板栏收紧，提示徽章隐藏以免挤成竖排 |
| ≤ 720px | 单栏 + 「代码 / 预览」标签切换；隐藏分隔条与徽章，代码区字号提到 16px（防 iOS 聚焦整页放大），下拉菜单与点击区域加大 |
| 高度 ≤ 460px（横屏） | 进一步压缩面板栏，把高度留给画布 |

- 高度用 `100dvh` 并适配 `safe-area-inset`，刘海屏和地址栏伸缩不会挤掉状态栏
- 画布 `touch-action:none`，手势全部自己处理：单指拖元素 / 空白处平移、双指捏合缩放并跟随中点、双击增删折点
- 滚轮与双指共用同一份 `zoomAtClient()`，缩放手感一致；放大后仍能精确定位到指针下方
- 隐藏面板期间不重算视图（`fitView()` 检测到 0 宽直接返回），切回预览时再适配一次

想目视检查各宽度下的表现，直接打开 `tests/viewport-check.html`（用 390 / 360 宽的 iframe 触发断点）。

## 🏗️ 技术架构

UMLite 是完全运行在浏览器中的单页应用，源码按职责分层：

```
UMLite.html ─┬─ css/style.css
             └─ js/
                 util.js         通用工具：el() / textWidth() / 全局字号系数
                 layoutcode.js   @layout 位置代码的唯一实现（读 + 写，双向一致）
                 parser.js       DSL 解析：parseDSL → parseClassLike / parseActivity / parseSequence
                 layout.js       布局算子：力导向、正交化、分层+Barycenter、消重叠、时序布局
                 pipeline.js     管线：buildModel() = 解析 → 尺寸 → 布局 → 应用 @layout
                 render.js       渲染层：SVG 图形与连线、时序图生命线 / 激活条 / 组合片段
                 view.js         视图与交互：paint()、缩放平移、十余种拖拽状态机、双指手势
                 undo.js         画布撤销/重做：拖拽前后拍模型快照，一次手势一步
                 export.js       SVG / PNG 导出
                 ui.js           顶栏、导入、反写代码、分隔条、菜单
                 samples.js      10 个内置示例
                 history.js      localStorage 历史记录
                 changelog.js    更新日志数据（由 docs/CHANGELOG.md 生成，勿手改）
                 notice.js       版本号胶囊 + 更新公告弹窗
                 main.js         启动
```

- **管线层**：`buildModel(src)` 是「DSL → 可渲染模型」的唯一入口，主应用与元素测试页共用它，避免两处各抄一份布局分支
- **解析层**：正则表达式 + 行解析器，将 DSL 文本转换为结构化模型；`@layout` 位置块的读（`parseLayoutBlock`）与写（`serializeLayoutBlock`）集中在 `layoutcode.js`，一份语法一处定义，读写不会漂移
- **布局层**：按图类型自适应 — 类图力导向后正交化（横平竖直）、活动图 / 状态图分层布局 + Barycenter 层间排序（降低交叉）、用例图边界分离布局（防重叠），并基于连通分量聚类进行初始排布；布局不使用随机数，同一份 DSL 每次结果完全一致
- **增量渲染**：`buildModel(src, { previous })` 先比对「结构签名」（剔除几何字段后的模型 JSON）与 `@layout` 块，一致时直接复用上次模型、跳过重排 —— 打字不打断画布，拖动结果也不会被冲掉
- **渲染层**：纯 SVG 渲染，支持拖拽、缩放、平移交互
- **零依赖**：不使用任何第三方库，纯原生 JavaScript + SVG（测试也只用 node 内置能力）

## 🧪 测试

零依赖、零安装，两种跑法：

```bash
node tests/run.mjs        # 全部：36 条 DSL 断言 + 22 项页面冒烟 + 4 项发布一致性
node tests/page.mjs       # 只跑页面级冒烟
node tests/release.mjs    # 只跑版本号 / 更新文档一致性
```

也可以直接双击 `tests/index.html` 在浏览器里看结果（与 node 共用同一套用例）。

| 文件 | 作用 |
|---|---|
| `tests/cases.js` | DSL 用例：10 种图、关系运算符、`@layout`、布局质量 |
| `tests/harness.js` | 断言收集器；每条用例还会自动附加三项不变量 — 几何数值必须有限、布局必须可复现、`@layout` 往返不得漂移 |
| `tests/page.mjs` | 在假 DOM 里按页面顺序加载全部脚本，验证启动渲染、增量跳过、10 个示例、反写回环、撤销/重做栈、更新公告 |
| `tests/release.mjs` | 发布一致性：版本号格式与顺序、`js/changelog.js` 与文档同步、README / 页面标签对得上 |
| `tests/run.mjs` | node 运行器（vm + 最小 DOM 桩），退出码可直接挂 CI |
| `test-elements.html` | 元素视觉清单页（人工看图形样式，非自动断言） |
| `tests/viewport-check.html` | 视口验证台：390 / 360 宽 iframe 触发窄屏断点，并跑一次双指捏合 |

新增语法或图形时，在 `tests/cases.js` 里补一条用例即可 —— 顺手就能发现方向、多重度、往返这类肉眼容易漏掉的问题（E-R 关系方向的不一致就是这样被抓出来的）。

## 🔖 版本号与更新公告

版本号形如 `1.XX`，其中 **`XX` 就是 git 提交次数**（`git rev-list --count HEAD`）。第 20 次提交即 `v1.20`，以此类推，不用手工维护主次版本。

发出一次更新时走三步：

```bash
# 1. 在 docs/CHANGELOG.md 顶部加一节（版本号 = 当前提交数 + 1）
# 2. 生成页面数据（js/changelog.js 已提交，勿手改）
node tools/sync-changelog.mjs
# 3. 确认四处对齐：更新文档 / 页面数据 / README 版本号 / 页面胶囊按钮
node tests/run.mjs
```

页面这一侧：

- 右下角常驻版本号胶囊，点开即可查看当前版本的更新内容与全部历史版本
- 首次打开、或版本号比上次看过的更新时自动弹出一次；已读版本记在 `localStorage`（键 `umlite.seenVersion`），之后不再打扰
- 内容来自 `js/changelog.js`，由 `docs/CHANGELOG.md` 生成 —— 运行时零依赖、`file://` 直接打开也能读（本地 md 会被 CORS 拦住，所以转成 JS 数据）
- `tests/release.mjs` 会卡住版本号不同步的提交，避免页面写着旧版本、公告却停在上一版
